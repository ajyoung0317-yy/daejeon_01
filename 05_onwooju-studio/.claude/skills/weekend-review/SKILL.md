## A. 준비 — 관람 전 (평일)

입력: 작품 이름. 개봉·공개일을 모르면 조사에서 찾는다.

1. **장부·폴더**: `회사/작품장부.md`에 줄을 추가하고 `output/[주제]/`, 보관함 `[작품]/` 폴더를 만든다.
2. **조사** (에이전트 1개, general-purpose): "`movie-blog-review` SKILL.md를 읽고 **1단계(조사)만** 해서 `output/[주제]/research.md`를 만들라." 개봉 전 작품이면 평단 반응은 "(개봉 전)"으로 둔다.
3. **감상 양식**: `회사/감상-양식.md`를 보관함 `[작품]/감상.md`로 복사한다(이미 있으면 그대로 둔다).
4. **스틸 점검**: 보관함 폴더의 이미지 수를 센다. 운영자에게 **글씨 없는 공식 스틸 8장 이상 + 포스터 1장**을 넣어 달라고 알린다(블로그 5 + 카드 6~7 + 릴스 7~9, 겹쳐 써도 됨).
5. **보고**: 조사 소스 수, 개봉일·러닝타임·등급, 관람 추천일(캘린더), 운영자 할 일(스틸, 관람)을 3~5줄로.

## B. 관람 후 — 감상 받기

1. 운영자가 감상을 주면(양식 그대로든 자유롭게든) **원문 그대로** 감상.md 칸에 옮긴다. 다듬지 않는다. 빈 칸은 `(미기록)`.
   - 별점이 없으면 묻는다. 별점 없이는 진행하지 않는다.
   - 배우·인물 이름이 research.md와 다르면 옮기기 전에 확인한다(디거 때 배우 이름 혼동).
   - 협찬·초대 여부가 없으면 한 번 묻는다.
2. 스틸이 8장 미만이면 알리고, 운영자가 "그대로 진행"이라고 하면 있는 만큼으로 간다.

## C. 초안 — 세 채널 동시에

서로 기다리지 않으므로 **에이전트 3개를 한 메시지에서 동시에** 부른다. 모두 research.md와 감상.md만 사실·감상의 출처로 쓴다.

| 채널 | 부를 것 | 지시 요점 | 산출물 |
|---|---|---|---|
| 블로그 | general-purpose | `movie-blog-review` SKILL.md를 읽고 **2~4단계**. ✍️ 자리는 감상.md 원문으로 채우고 별점도 감상.md 그대로 | `output/[주제]/final.md`, `final.html`, `images/` |
| 카드뉴스 | general-purpose | `card-news` SKILL.md를 읽고 리뷰(노랑) 7장을 **멈추지 말고** 끝까지: 번호 정하기 → 사진 복사·이름 붙이기 → 감상.md로 장 구성 → 틀 채우기 → 사진 중심 맞추기(`-Check` 시트 확인) → PNG → caption.txt. 운영자에게 물을 것은 "확인 필요"로 모아 돌려준다 | `posts/NN_[작품]_리뷰/` |
| 릴스 | `shorts-planner` (기획 모드) | brief.md는 디렉터가 먼저 만든다(작품, 30초 #온우주리뷰, 리뷰 번호는 카드뉴스와 같게). `plan.md` + `upload.md`까지 | `output/[주제]/shorts/01_plan/` |

- 지시문에는 6요소를 넣는다: 프로젝트 폴더 · 먼저 읽을 파일 · 할 일 · 산출물 경로 · 완료 기준 · 쓰기 허용 폴더.
- 리뷰 번호: 카드 에이전트가 정한 번호를 릴스 brief에도 쓴다. 동시에 부르므로 디렉터가 `posts/` 폴더 수를 먼저 세어 번호를 정해 두 지시문에 같이 넣는다.

## D. 검수 — 한 번에

세 초안이 모이면 `brand-reviewer`를 **채널마다 새로 하나씩, 동시에** 부른다(블로그 `final.md` / 카드 PNG·caption.txt / 릴스 plan.md·upload.md). 판정은 디렉터가 `output/[주제]/reviews/blog.md`, `card.md`, `01_plan.md`(릴스는 `shorts/reviews/`)에 저장한다.
- 형식·사실 문제(글자 수, 출처, 표기)는 운영자에게 묻지 않고 만든 에이전트에게 돌려보내 **한 번** 고친다.
- 운영자 판단이 필요한 것(스포 신호, 감상 문장 바꾸기, 협찬 표기)만 E로 모은다.

## E. 운영자 확인 ① — 초안 고르기

AskUserQuestion **한 번**에 최대 4문항으로 묻는다. 보통:
1. 릴스 훅 3안 중 하나
2. 블로그 제목(감성 한 줄) 확인
3. 검수가 올린 운영자 판단 1~2개
그 밖에 보여 줄 것: 카드 `_check/sheet.png` 경로, 블로그 `final.html` 경로. 결정은 `output/[주제]/shorts/decisions.md`에 기록한다.

## F. 마무리 제작

1. 블로그·카드: 운영자 수정이 있으면 만든 에이전트(SendMessage로 이어서)가 반영한다. 카드는 `업로드용/` 정리까지.
2. 릴스: `shorts-designer` → `shorts-planner`(검토 모드) → 필요하면 디자이너 1회 수정 → `shorts-editor` → `brand-reviewer`(최종). 장면 PNG는 디렉터가 PIL 한 장 모음으로 직접 한 번 본다.

## G. 운영자 확인 ② — 완성본

- 보여 줄 것: 블로그 `final.html`, 카드 `업로드용/`, 릴스 mp4(SendUserFile)와 `upload.md`
- 업로드 체크리스트: 블로그 발행(스틸 업로드), 카드 업로드, 릴스 업로드(음악은 인스타 제공 음원만), 협찬 표기 여부
- 업로드는 운영자가 직접 한다.

## H. 정리

- `회사/작품장부.md` 그 작품 줄 갱신, 캘린더 해당 칸에 ✅
- `회사/learnings.md` 한 줄 (이번에 운영자 확인이 몇 번이었는지 포함)
- 운영자가 숫자를 알려 주면 `회사/성과/콘텐츠별.csv`에 넣는다(올린 뒤 며칠 지나서)
- 커밋할지 묻는다. 스킬을 고쳤으면 `py tools/backup_skills.py` 먼저.
