# 영화·드라마 블로그 리뷰 글

운영자는 어린이집에서 8년 일한 경험이 있는 영화·드라마 추천 블로거다. 넷플릭스 추천 블로그로 시작했지만 지금은 **극장 개봉작과 OTT 작품을 가리지 않는 영화 추천 블로그**다. 특정 플랫폼을 블로그의 정체성으로 내세우지 않는다. 글의 강점은 정보 정리에 더해 **"누구와, 언제 보면 좋은지"**를 골라 주는 것이다. 이 스킬은 지금까지 함께 만든 리뷰 6편(가능한 사랑, 디거, 로또 1등도 출근합니다, 하트 오브 비스트, 와일드 호스 나인, 11월 극장 개봉작)의 형식과 운영자가 직접 고친 규칙을 묶은 것이다.

완성 예시는 단일 리뷰 `references/example-review.md`(와일드 호스 나인, 운영자 수정 반영 최신본)와 큐레이션 `references/example-curation.md`(2026년 11월 극장 개봉작 9편)다. 쓰려는 글 종류에 맞는 예시를 **글을 쓰기 전에 반드시 한 번 읽는다.** 같은 틀에 작품명만 바꿔 찍어내지 말고, 리듬과 밀도를 맞추는 기준으로 쓴다.

## 우리 블로그 고정 규칙 (모든 가이드보다 우선)

운영자가 직접 고친 규칙이다. references 가이드와 다르면 이쪽을 따른다.

1. **표 금지.** 글에 마크다운 표를 쓰지 않고, 비교 표 이미지도 만들지 않는다. 비교가 필요하면 문장이나 이모지 목록으로 풀어 쓴다. research.md·작성 메모 같은 내부 파일에도 표를 쓰지 않는다. 여러 항목을 비교할 때는 `- **항목** — A: … / B: … / 비고: …` 같은 목록으로 쓴다.
2. **누구와 보면 좋을까?** 혼자 줄은 `👤 :`, 친구·연인·가족 등 함께 보는 줄은 `👥 :`.
3. **별점은 온우주별점 블록.** 후기 섹션에 `references/rating-guide.md` 형식 그대로. 이름은 항상 "온우주별점". 점수·한 줄 평은 초안으로 채우고 바로 아래 ✍️ 수정 안내를 둔다. 프리뷰(공개 전) 글에는 넣지 않는다.
4. **경험을 지어내지 않는다.** 나는 작품을 보지 않았다. 시청 소감·장면 인상은 `✍️ [직접 작성: 무엇을 쓰면 좋은지]` 자리로 남긴다(최소 3곳). 배우·장면 문장은 조사한 사실과 평단 반응으로만 쓴다.
   - **단, 작품 폴더에 `감상.md`가 있으면** 그 문장을 ✍️ 자리에 미리 넣는다. 형식: `✍️ [감상.md에서: "운영자 원문"]` — 원문을 그대로 옮기고 다듬지 않는다. 온우주별점 점수·한 줄 평도 감상.md에 있으면 그대로 쓴다(초안 별점을 만들지 않는다). 감상.md에 없는 칸만 기존처럼 비워 둔다.
5. **노스포.** 결말·반전은 어디에도 쓰지 않는다.
6. **사실은 조사한 것만.** 개봉일·러닝타임·등급·출연·수치·발언은 research.md에 출처가 있는 것만.
7. **제목 형식:** `작품명 + 영화 리뷰(또는 핵심 키워드: 배우 이름·플랫폼·기본정보) | 감성 한 줄`. 감성 한 줄은 작품 주제를 독자에게 묻는 질문형이 좋다(물음표 생략 가능). 예: `와일드 호스 나인 영화 리뷰 | 당신의 곁에도 끝까지 남아 줄 사람이 있나요`, `하트 오브 비스트 브래드 피트 영화 | 여러분 곁에 '오딘'은 누구인가요`, `2026년 11월 극장 개봉 영화 기대작 9편 | 넌 어떤 작품 부터 볼래?`
8. **공식 스틸은 정확히 5장:** ① 기본 정보(포스터) ② 배우 섹션 맨 위 대표 배우 스틸 1장 ③ 줄거리 ④ 관람 포인트 ⑤ 후기. 배우별·커플별 스틸 칸은 따로 만들지 않는다. (드라마 리뷰는 `references/drama-guide.md`의 배치를 따른다)
9. **본문 사진은 원본 그대로.** 공식 사진을 창 프레임에 넣지 않고, 단계·카드·인용 같은 설명용 도식 이미지도 만들지 않는다. 썸네일(사진 위 라벨 + 2줄 문구)만 만든다. 이미지 합계가 6장보다 적어도 괜찮다. (2026-11-11 운영자 요청)
10. **드라마는 드라마 틀로.** 드라마(OTT 시리즈·방송 드라마) 리뷰는 아래 영화 리뷰 뼈대를 쓰지 않고 `references/drama-guide.md`와 `references/example-drama-review.md`를 따른다. 10년째 한국 드라마를 보는 드라마 광의 시선으로 정주행 정보·진입장벽·커플 구도·드라마 온도계·비슷한 드라마 추천을 담는다.

## 결과물 위치

- 작업 폴더에 `output/`이 있으면 `output/[주제]/`, 없으면 현재 폴더에 `output/[주제]/`를 만든다.
- `[주제]`는 띄어쓰기를 `-`로: `output/하트-오브-비스트/`.
- 같은 이름의 파일이 이미 있으면 덮어쓰지 말고 사용자에게 묻는다(원고는 `draft-2.md`로).

```
output/[주제]/
├── research.md        1단계
├── draft.md           2단계 (3단계에서 이미지 경로로 치환)
├── images/
│   ├── source/        사람이 넣는 공식 포스터·스틸 (있으면 썸네일 배경)
│   ├── html/          이미지 HTML 원본
│   ├── thumbnail.png
│   └── body-N.png
├── final.md           4단계: 발행용 원고
└── final.html         4단계: 미리보기 + 「발행 전 확인」 상자
```

## 진행 순서

네 단계를 순서대로 한다. **단계가 끝날 때마다 사용자에게 1~2줄로** 무엇이 끝났고 핵심 수치(소스 수, 글자 수, 이미지 수)와 다음 단계를 알린다. 사용자가 "원고만", "조사만"처럼 범위를 정하면 그 단계까지만 한다.

### 1단계. 조사 → `research.md`

- 오늘 날짜를 기준으로 최신 자료를 찾는다. 검색어에 연도·월을 넣는다.
- **신뢰할 만한 소스 5개 이상.** 우선순위: 공식(배급사·제작사·OTT 플랫폼·영화제·영화진흥위원회) > 주요 언론 > 전문 매체(씨네21 등). 협찬·체험단·홍보 글, 출처·날짜 없는 글은 뺀다. 중요한 정보는 원문을 직접 열어 확인한다. (blog.naver.com 등 일부 네이버 페이지는 열리지 않으니 다른 소스를 찾는다.)
- 작품이면: 공개·개봉일, 감독·출연·배역, 러닝타임·회차, 등급, 줄거리 설정, 영화제·수상, 평단·관객 반응(점수는 날짜와 함께), 극장 개봉작이면 상영관·특전·쿠키, OTT 작품이면 플랫폼·회차 공개 방식, 지난 작품이면 지금 볼 수 있는 곳(극장 재개봉·OTT).
- 영화제·수상 이력은 **날짜(연·월·일)까지** 확인해 적는다. "지난 3일"처럼 상대 날짜면 기사 작성일로 환산한다. 원고와 단계 이미지에서 시간 순서를 틀리지 않기 위해서다.
- 모든 정보 뒤에 출처 번호 `[1][3]`. 수치·이름은 소스 그대로. 엇갈리는 정보는 양쪽 다 적는다.
- 구성: 조사일·소스 수·한 줄 요약 → 핵심 정리(5~10줄) → 소주제 섹션 → 정보가 엇갈리는 부분(목록, 표 금지) → 확인하지 못한 것 → 참고 소스 목록(제목·URL·매체·날짜·유형). 스포일러는 필요할 때만 「스포일러 주의」 섹션에.

### 2단계. 원고 → `draft.md`

먼저 `references/style-guide.md`, `references/seo-guide.md`, `references/rating-guide.md`, 글 종류에 맞는 예시(`example-review.md` 또는 `example-curation.md`)를 읽는다. 두 가이드가 다르면 seo-guide, 고정 규칙과 다르면 고정 규칙.

**글 종류:**
- 개봉·공개 전 → 프리뷰
- 개봉·공개 후 → 단일 작품 리뷰 (영화는 아래 뼈대, **드라마는 `references/drama-guide.md` 뼈대**)
- 여러 편 → 큐레이션. 월별 개봉작 정리뿐 아니라 **테마 추천**("혼자 보기 좋은 영화", "부모님과 볼 영화")도 여기에 속한다. 극장·OTT 작품을 섞어도 되고, 작품마다 🎬👫📍⏱️🚫📅📺 + 📄🔎👥 블록을 반복한다. 📺 줄에 지금 볼 수 있는 곳(극장 상영 중 / 넷플릭스 등)을 적는다.

**플랫폼 표기:** 제목·도입에서 "넷플릭스"를 기본값으로 쓰지 않는다. 작품이 실제로 공개된 곳만 정확히 쓰고(극장 개봉 영화 / 넷플릭스 영화 / 티빙 드라마 등), 제목에는 필요할 때만 한 번.

**단일 리뷰 뼈대** (예시 글 참고):

```
# 작품명 영화 리뷰 | 감성 한 줄   (고정 규칙 7번, 앞 20자 안에 작품명)
**[극장 개봉 영화 / OTT명 영화·드라마] [작품명]을 리뷰합니다.**

## [작품명] 누구와 보면 좋을까?
<sub>함께 보기 좋은 사람과 상황을 정리합니다.</sub>
요약 한 줄
👤 : 혼자 [상황]에 보기 좋습니다. [이유].
👥 : [대상]과 [상황]에 보기 좋습니다. [이유].
맞지 않는 대상 한 문장 (아이와 볼 때 주의할 장면 종류를 스포 없이)
## 후기
<sub>보고 난 뒤 감상을 남깁니다.</sub>
[이미지: 창 프레임 / …]
온우주별점 블록 + ✍️
마무리 2문단 (관련 글 [내 글 링크]) + "선택에 도움이 되길 바랍니다."

#해시태그 5~10개
```

**문체:** "~입니다/~습니다" 합쇼체, 문단 1~3문장, 한 문장 50자 안팎. `~이었죠`, `~인데요`는 한 글에 2~3번. 이모지는 항목 라벨로만(본문 문장 끝 금지). 색 강조는 `<span style="color:#0b8a5f">…</span>`, 문단당 1곳 이하·글 전체 5~8곳. 정보 목록 6줄은 "입니다" 없이 값만, 줄 끝 공백 2칸.

**이미지 자리:** 공식 사진 5장(고정 규칙 8·9번). 설명용 도식 `[IMAGE: …]`는 운영자가 따로 원할 때만 넣는다.
- 공식 스틸·포스터 자리 `[이미지: 장면 설명]` + `<sub>설명 ⓒ 배급사 또는 플랫폼명</sub>` — 3단계에서 보관함 사진 원본으로 채운다.

**작성 메모:** 파일 맨 위에 `<!-- -->` 작성 메모를 둔다. 아래 대괄호 이름은 3·4단계가 찾는 키이므로 바꾸지 않는다.

```
<!--
==================== 작성 메모 (발행 시 삭제) ====================
글 종류 : 단일 작품 리뷰
권장 발행일 : YYYY-MM-DD ~ MM-DD
발행 주제 분류 : 영화 / 드라마

[썸네일] 1080x1080, 글씨 화면 25% 이하, 라벨 + 2줄
  라벨 : 공개 예정 / 영화 리뷰 / 드라마 리뷰 / 영화 큐레이션
  1줄 : (14자 이내)
  2줄 : (14자 이내, 이모지 1개까지)
  이미지 : 쓸 공식 배포 이미지 설명

[발행 전 꼭 할 일]
  1. ✍️ 표시 N곳을 직접 쓴 경험 문장으로 채우기 (온우주별점 점수·한 줄 평 확인 포함)
  2. 공식 페이지에서 개봉일·러닝타임·등급 재확인
  3. [이미지: …] 자리에 공식 배포 스틸 넣기
  4. [내 글 링크] 자리에 관련 글 링크 (없으면 문장 삭제)

[사용한 출처]
  [1] 매체명, YYYY-MM-DD  URL  - 쓴 정보

[확인 필요]
  - 항목: 이유 (없으면 "없음")
==================================================================
-->
```

**저장 전 자체 검수** (실제로 세어 보고 벗어나면 고친다): 제목 형식(작품명 영화 리뷰 | 감성 한 줄)·앞 20자 안 작품명 / 공식 스틸 정확히 5곳(드라마는 5~6곳) / 본문 1,500~2,500자(공백 제외, 드라마 2,000~3,000자, 큐레이션은 작품당 400~600자) / 제목 외 작품명 6회 이하 / 소제목 4~7개(드라마 6~9개), 2~3개 질문형 / 색 강조 5~8곳 / ✍️ 3곳 이상 / 해시태그 5~10개 / **마크다운 표 0개** / 👤·👥 구분 / 온우주별점 블록 형식 / 모든 사실이 research.md에 있음.

### 3단계. 이미지 → `images/`

`references/image-guide.md`를 읽는다. 템플릿은 `assets/image-templates/`(기본), `assets/image-templates/film/`(진지한 작품용 영화 톤, 단계만).

0. **공식 스틸 채우기:** 위 「공식 스틸 보관함」에서 그 작품 폴더를 찾는다(없으면 이 단계는 건너뛰고 `[이미지: …]` 자리를 남긴다).
   1. 폴더 사진을 PIL로 번호 붙인 한 장짜리 모음(contact sheet)으로 만들어 Read로 본다. 모음은 scratchpad에 둔다.
   2. 고정 규칙 8번의 5자리에 맞는 사진을 고른다: 포스터(`poster`, 세로 메인 포스터), 배우 맨 위(`main`, 주연이 잘 보이는 장면), 줄거리(`story`), 관람 포인트(`point`, 원고가 말하는 볼거리와 맞는 장면), 후기(`review`). 같은 사진을 두 번 쓰지 않는다. 인물 이름은 원고의 자리 설명과 맞는 장면일 때만 캡션에 쓴다.
   3. 고른 원본을 `images/source/still-[키].jpg`로 **복사**한다(보관함 원본은 그대로).
   4. 같은 사진을 `images/[키].jpg`로도 복사한다. 창 프레임 캡처는 하지 않는다(고정 규칙 9번).
   5. draft.md의 `[이미지: …]` 줄을 `![대체 텍스트 한 문장](images/[키].jpg)`로 바꾼다. 아래 `<sub>캡션 ⓒ 배급사</sub>`는 그대로 둔다.
   - 포스터 하단의 등급·공개일 표기도 확인한다. 기사에 없는 등급을 공식 포스터에서 확인하면 research.md에 "공식 포스터 표기"로 적는다.
   6. 썸네일 배경도 이 중 한 장(보통 `main`)을 쓴다.
1. **썸네일:** `0-thumbnail.html` 복사 → `images/html/thumbnail.html`. 문구는 작성 메모 `[썸네일]`. `images/source/`에 공식 이미지가 있으면 배경으로 쓰고, 인터넷에서 이미지를 받아 넣지 않는다.
2. **본문:** (원고에 `[IMAGE: …]`가 없으면 건너뛴다. 운영자가 도식을 따로 원할 때만) `[IMAGE: …]` 마커를 위에서부터 번호 매겨 템플릿을 고르고 `<body>` 안만 바꿔 `images/html/body-N.html`로. `:root` 색 토큰·프레임은 그대로.
3. **캡처:** 이 스킬 폴더의 `scripts/capture.py`로 한 번에.
   ```bash
   py "<스킬폴더>/scripts/capture.py" output/[주제]/images/html/thumbnail.html output/[주제]/images/thumbnail.png output/[주제]/images/html/body-1.html output/[주제]/images/body-1.png
   ```
   `py`가 없으면 `python`. playwright가 없으면 `py -m pip install playwright` (설치된 Edge 사용).
4. **검수:** PNG를 Read로 직접 열어 잘림·넘침·빈 여백·□ 글자·썸네일 글씨 25% 초과를 확인. 이미지마다 최대 3회 고쳐 찍고, 남으면 보고.
5. **치환:** draft.md의 `[IMAGE: …]` 줄을 `![대체 텍스트 한 문장](images/body-N.png)` + `<sub>이미지 제목</sub>`으로 바꾸고, 작성 메모 `[썸네일]`에 `파일 : images/thumbnail.png` 추가. 본문의 다른 글자는 바꾸지 않는다. `[이미지: …]`는 건드리지 않는다.

### 4단계. 통합 → `final.md`, `final.html`

```bash
py "<스킬폴더>/scripts/assemble.py" output/[주제]
```
`markdown` 모듈이 없으면 `py -m pip install markdown`. 결과를 점검한다: 없는 이미지 파일 0, 남은 `[IMAGE:]` 0, thumbnail.png 있음, final.md가 `# 제목`으로 시작. 문제가 있으면 해당 단계로 돌아가 고친다.

## 마지막 보고

- 파일 경로(final.html, final.md, images/)
- 점검 수치: 제목 글자 수, 본문 글자 수, 이미지 수(공식 자리 / 만든 이미지), ✍️ 자리 수
- 운영자가 할 일: ✍️ 채우기, 온우주별점 점수·한 줄 평 다듬기, 공식 스틸 넣기, 확인 필요 항목, 썸네일 업로드
- 발행 방법: final.html을 브라우저로 열고 「발행 전 확인」 상자를 뺀 본문을 복사해 네이버 에디터에 붙여 넣은 뒤, 이미지는 `images/`에서 직접 업로드

## 하지 말 것

- 마크다운 표, 비교 표 이미지
- 보지 않은 작품의 감상을 본 것처럼 쓰기, ✍️ 자리를 지어낸 경험으로 채우기
- 결말·반전 언급, 근거 없는 최상급("역대 최고"), 연속 느낌표, 인터넷 줄임말
- 기사·다른 블로그 문장 그대로 옮기기, 공식 배포가 아닌 이미지 안내
- "다시보기", "무료보기" 같은 불법 시청 연상 키워드
