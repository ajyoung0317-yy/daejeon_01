# 온우주 영상팀 구상 (v0.2)

> 작성일: 2026-11-11 · 상위 문서: [운영계획서](운영계획서.md) 7장 "영상팀 — 새로 필요", [브랜드 가이드](브랜드-가이드.md)
> 참고: 「영상 에이전트 팀」 소개 페이지 (디렉터 1명 + 전문 에이전트 11명, 9단계 운영)
> 표시: **[확인]** = 운영자가 정할 것

## 0. 한눈에 보기

- **만들 것**: 유튜브 쇼츠·인스타 릴스용 **30~45초 세로 영상** (1080×1920). 같은 영상을 두 곳에 올린다.
- **팀**: 디렉터(메인 대화) + 에이전트 **4명** (기획, 화면, 편집, 검수). 참고 팀의 11명은 광고 대행용이라 1인 채널에는 무겁다.
- **참고 팀에서 가져오는 것**: 디렉터만 에이전트를 부르는 구조, 파일 인수인계, **다른 에이전트가 검토**, 근거 꼬리표, 배움 기록(learnings).
- **재료**: 블로그용 `research.md` + 운영자 감상 + 공식 스틸. 새로 조사하지 않는다 (원 소스 멀티 유즈).
- **만드는 작품**: **새로 보는 작품으로만** (2026-11-11 운영자 결정). 하트 오브 비스트 쇼츠는 흐름을 시험한 시험작이고 올리지 않는다.
- **첫 형식**: 공식 스틸 + 자막 **슬라이드형 영상**. **목소리 없이 자막만** (2026-11-11 결정). 예고편 클립은 기본으로 쓰지 않는다.
- **만든 것**: 에이전트 4개(`.claude/agents/shorts-planner·shorts-designer·shorts-editor·brand-reviewer.md`), 세로 장면 틀 3종(`guides/shorts-templates/`), 배움 기록(`회사/learnings.md`)

## 1. 참고 팀에서 가져올 것과 바꿀 것

| 참고 팀의 원리 | 온우주에서는 | 이유 |
|---|---|---|
| **허브 앤 스포크** — 디렉터만 에이전트를 부른다 | 그대로. 블로그 라인(`CLAUDE.md`)도 이미 같은 구조 | 서브 에이전트는 서로 부를 수 없다 |
| **파일이 기억이다** — `handoffs/` 인수인계서 | 그대로. 다만 양식을 4줄로 줄인다 | 단계가 4개뿐이라 긴 양식은 낭비 |
| **남이 검토한다** — 작성자가 자기 결과를 검토하지 않는다 | 그대로. **검수 에이전트를 새로 호출**해 검토 | 스포·사실 오류는 쓴 사람이 못 본다 |
| **근거 사슬** E·I·M | **근거 꼬리표 3종**으로 단순화 (3장) | 광고 전략 단계가 없고, 근거는 research.md 출처 번호로 충분 |
| 전문가 11명 | **4명으로 합침** (2장) | 주 5~15시간 운영. 호출마다 비용·시간이 든다 |
| 9단계 | **6단계** (4장) | 전략·포트폴리오·웹 단계는 1단계 사업에 없음 |
| `learnings.md` 배움 기록 | 그대로. **블로그·인스타·영상 공통 하나**로 | 브랜드 전체가 같이 똑똑해지게 |
| "할 수 없는 일 → 대신 하는 일" 표 | 그대로 (6장) | 기대치를 미리 맞춘다 |

> 참고 팀의 11명 구성(전략·카피·아트·성과·포트폴리오 등)은 **3단계 마케팅 대행**을 시작할 때 다시 꺼내 쓴다.

## 2. 팀 구성

| 에이전트 | 맡는 일 | 읽는 것 | 쓰는 것 (`output/[주제]/shorts/` 아래) | 검토자 |
|---|---|---|---|---|
| **디렉터** (메인 대화) | 접수, 호출, 인수인계 경로 넘기기, 충돌 조정, 최종 보고, learnings 기록 | 전부 | `brief.md`, `decisions.md`, `reviews/` (검수 결과 대신 저장) | — |
| **shorts-planner** 기획 | 훅 3안, 장면표(초·틀·사진·자막·근거), 업로드 문구 | research.md, 운영자 감상, 브랜드 가이드 | `01_plan/plan.md` | 검수 |
| **shorts-designer** 화면 | 장면별 1080×1920 화면을 HTML로 만들고 PNG로 캡처 | plan.md, 공식 스틸, 브랜드 색·로고 | `02_frames/*.html`, `*.png` | 기획 |
| **shorts-editor** 편집 | 장면 PNG → 영상, 자막·전환·음량, 출력 확인 | 02_frames, script.md | `03_edit/[주제]_v1.mp4`, `edit_log.md` | 기획 |
| **brand-reviewer** 검수 (**최종 관문**) | 스포, 사실 근거, 저작권, 브랜드 말투·표기 확인. **파일을 쓰지 않는다** | 산출물 + 브랜드 가이드 + research.md | 판정 텍스트 → 디렉터가 저장 | — |

- **brand-reviewer는 영상 전용이 아니다.** 블로그 원고와 카드뉴스 검수에도 그대로 쓴다. 영상팀을 만들면서 회사 공통 검수자를 하나 얻는 셈이다.
- 목소리 없이 자막만 쓰고, 음악은 운영자가 업로드할 때 넣는다 (5-3).

## 3. 근거 꼬리표

참고 팀의 근거 사슬(E·I·M)을 온우주에 맞게 줄였다. **대본과 자막의 모든 문장**에 꼬리표를 단다. 꼬리표가 없는 문장은 검수에서 통과하지 못한다.

| 꼬리표 | 뜻 | 예 |
|---|---|---|
| `[S3]` | research.md 출처 3번에서 확인한 사실 | "11월 6일 넷플릭스 공개" `[S3]` |
| `[운영자]` | 운영자가 직접 한 말·별점. **에이전트가 지어내지 않는다** | "엔딩 크레딧까지 못 일어났어요" `[운영자]` |
| `[미확인]` | 확인하지 못함. 영상에 넣지 않고 운영자에게 보고 | — |

- 꼬리표는 `plan.md` 장면표의 '근거' 칸에만 단다. 화면에는 넣지 않는다.
- 별점은 항상 `[운영자]`다. 초안 별점을 영상에 넣지 않는다.

## 4. 운영 6단계

| 단계 | 누가 | 하는 일 | 산출물 |
|---|---|---|---|
| **1. 접수** | 디렉터 | 작품, 영상 종류(5-1), 운영자 감상 3줄과 별점을 받는다. research.md가 없으면 블로그 라인의 `researcher`를 먼저 부른다 | `brief.md` |
| **2. 기획** | 기획 → **검수** | 훅 3안 중 추천 1개, 장면표와 자막, 업로드 문구. 검수가 스포·근거·말투를 본다 | `plan.md`, `reviews/01_plan.md` |
| **3. 운영자 확인** | 운영자 | 훅과 대본을 고른다·고친다. **여기서만 방향을 바꾼다** | `decisions.md` |
| **4. 화면** | 화면 → **기획** | 장면 PNG 제작. 기획이 "구성안대로인가"를 본다 | `02_frames/`, `reviews/02_frames.md` |
| **5. 편집** | 편집 → **검수(최종)** | 영상 출력, 길이·해상도·소리 확인. 검수가 최종 판정 | `03_edit/*.mp4`, `reviews/03_final.md` |
| **6. 보고** | 디렉터 | 결과물 위치, 운영자가 할 일(업로드, 음악), learnings에 한 줄 | `final-report.md`, `회사/learnings.md` |

### 지시문과 보고 규칙 (참고 팀 그대로)
- **지시문 6요소**: 프로젝트 폴더 · 먼저 읽을 파일 · 할 일 · 산출물 경로 · 완료 기준 · 쓰기 허용 폴더
- **돌려주는 답은 짧게**: ① 산출물 경로 ② 핵심 결정 3줄 이내 ③ 미해결·확인 필요
- **덮어쓰지 않는다**: 수정본은 `_v2`, `_v3`로 새로 만든다.
- **인수인계서 4줄** (`handoffs/[단계].md`): 한 일 / 핵심 결정과 이유 / 미해결 / 다음 사람이 먼저 읽을 파일
- **검토 판정 3가지**: 통과 / 수정 후 통과 / 재작업. 문제마다 위치·이유·대안을 적는다.

### 폴더
```
output/[주제]/shorts/
├─ brief.md, decisions.md, final-report.md
├─ 01_plan/      plan.md (장면표·자막·업로드 문구)
├─ 02_frames/    _base.css, source/, scene-01.html … scene-09.png
├─ 03_edit/      scenes.txt, [주제]_v1.mp4, edit_log.md
├─ handoffs/
└─ reviews/
```

## 5. 영상 형식

### 5-1. 시리즈 (브랜드 가이드 시리즈 색을 그대로)
| 시리즈 | 길이 | 구성 | 포인트 색 |
|---|---|---|---|
| **30초 #온우주리뷰** | 30~40초 | 훅 → 작품 소개 → 좋았던 점 3 → 온우주별점 → 👥 누구와 | 노랑 |
| **오늘 뭐 보지? 3편** | 40~50초 | 상황 훅("비 오는 주말이라면") → 3편 × 10초 → 질문 | 노랑 |
| **이번 주 개봉작** | 30~45초 | 날짜순 3~5편, 편당 한 줄 | 블루 |

### 5-2. 화면 규칙
- **1080×1920**, 30fps. 장면당 3~5초, **첫 2초 안에 훅** 자막.
- **안전 영역**: 쇼츠·릴스는 아래쪽(제목·버튼)과 오른쪽(좋아요 버튼)을 화면 UI가 가린다. 자막과 로고는 **위아래 각 15%, 오른쪽 12%를 비운 안쪽**에 둔다.
- 로고 `onspace.film_` (점은 빨강) 왼쪽 위에 항상. 마지막 장면은 계정 이름 + 질문.
- 글꼴은 Pretendard, 자막은 한 장면 2줄·줄당 14자 이내.
- **🔒 스포 없어요**를 첫 장면이나 둘째 장면에 작게.

### 5-3. 목소리와 음악 — **자막만으로 시작** (2026-11-11 결정)
| 선택지 | 장점 | 단점 |
|---|---|---|
| A. **자막만** + 음악 | 가장 빠름, 지금 바로 가능 | 몰입도가 낮을 수 있음 |
| B. **AI 음성(TTS)** | 매번 같은 목소리, 자동화 쉬움 | 기계 느낌, 도구 설치 필요 |
| C. **운영자 목소리** 녹음 | 가장 "사람" 같고 협찬 때 강점 | 녹음 시간이 든다 (편당 5분 안팎) |

- **A(자막만)로 시작했다.** 시험 몇 편으로 흐름이 잡히면 C(운영자 목소리)로 옮겨 가는 것을 검토한다. 브랜드 약속("감상은 사람이 쓴다")과 협찬 목표에는 C가 가장 잘 맞는다.
- 영상 파일에는 무음 트랙만 넣는다 (업로드 호환용).
- 음악은 에이전트가 **분위기만 제안**하고, 운영자가 업로드할 때 플랫폼에서 제공하는 음원으로 고른다. 라이선스 판단은 에이전트가 하지 않는다.

## 6. 할 수 없는 일 → 대신 하는 일

| 할 수 없는 일 | 대신 하는 일 |
|---|---|
| 영상·이미지 생성 AI로 장면 만들기 | 공식 스틸 + HTML 디자인 화면 |
| 예고편 클립 자르기 (권리 확인 불가) | 기본은 쓰지 않는다. 배급사가 홍보용으로 허락한 경우에만 운영자가 넣는다 |
| 음원 고르기·라이선스 확인 | 분위기·빠르기 제안 |
| 업로드·예약 발행 | 제목·설명·해시태그 초안까지 |
| 조회수 직접 조회 | 운영자가 준 숫자로 월간 분석 (성과팀이 생기면) |
| 저작권 최종 판단 | "확인 필요"로 표시해 운영자에게 넘긴다 |
